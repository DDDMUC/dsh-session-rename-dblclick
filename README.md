# dsh-session-rename-dblclick

会话标题就地改名 —— 侧边栏那一行、顶栏那一条，两处都生效。

## 用法

两处的进入手势**不一样**，因为单击语义不同：

| 位置 | 手势 | 为什么 |
| --- | --- | --- |
| 顶栏标题（面包屑） | **单击** | 产品里点击它什么都不做，所以一击即改（与参考实现一致：盒子一直在，点一下把内容换成输入框） |
| 侧边栏会话行标题 | **双击** | 单击是「打开这个会话」，不能被改名抢走 |

进去之后：标题原地变成输入框（已全选），直接打字；`Enter` 或点别处保存，`Esc` 取消；内容没改或清空则不提交。

## 它是怎么做的

- **客户端**：`document` 捕获阶段的 `click` / `dblclick` 监听。命中
  `[class*="_sessionRow"] [class*="_title"]` 或 `[class*="_crumbCurrent"]` 后，
  在标题位置浮起一个盒子：**盒子带边框与内距，但用负偏移把它们抵掉**，
  所以文字一个像素都不动，进入/离开编辑只看到边框与阴影出现或消失。
  盒子尺寸取自标题的实测行盒（40px 高 / 22px 圆角 / 8px 12px 内距；侧栏行
  这种窄面按 4px、3px 缩放，免得出框压到邻居）。输入框自己什么都不画
  （`border:0; padding:0; background:transparent; font:inherit`）。
  编辑期间标题设成 `visibility: hidden`，关闭时原样还原；只改可逆的样式与
  文本，不替换任何 slot，也不动 React 的节点结构；模块带单例标记，重复激活
  不会叠出两个输入框。
- **宿主**：`POST /dsh-session-rename/rename { sessionId, title }`，仅限
  loopback + 同源请求；内部调用产品自带的 `sessionController.rename`，所以
  标题事件、侧边栏/顶栏投影都和「…」菜单里的重命名完全一致。

## 说明

- 选择器依赖 CSS Module 的**局部类名后缀**（`_sessionRow` / `_title` /
  `_crumbCurrent`），不依赖每次构建都会变的哈希前缀；产品大改结构时可能需要跟着调一次。
- 没有 host half 时，双击仍会打开输入框，但保存会提示「改名接口没有响应」。
